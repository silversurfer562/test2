# Plan: Cost joined to quality

**Spec**: [docs/specs/cost-in-quality-gate/](../../docs/specs/cost-in-quality-gate/)
**Created**: 2026-09-11

---

## Summary

attune-rag measures selectivity and does not measure economics. `src/attune_rag/benchmark.py::_run_benchmark` returns `retriever`, `corpus`, `total_queries`, `precision_at_1`, `recall_at_k`, `k`, `mean_latency_ms`, `max_latency_ms`, `by_difficulty`, `per_query` (benchmark.py:194-205) — ten keys, none of them a dollar figure. The locked gate at `docs/specs/release-quality-baseline/thresholds.json` carries three rows (`precision_at_1`, `recall_at_3`, `mean_faithfulness`), all quality. The product thesis is "selectivity × economics"; the README's hero table states the first half in four figures and the second half nowhere. Shipping this plan makes "the lightweight tier is the cheap one" a measured claim with a dated price stamp behind it instead of an architectural assertion.

The research pass contradicted the brief on eight points and the code wins each one; they are enumerated with their settling file:line inside T1's objective, where the parser can carry them to whoever executes that task. Two of them set the shape of everything downstream. **The price table is not in `cost_tracker.py`**: line 27 is `from attune.models import MODEL_REGISTRY` (the package) and line 28 is `from attune.models.registry import ADDITIONAL_MODELS, TIER_PRICING` (the submodule); only a 3-key `legacy_models` dict is local (cost_tracker.py:54-59). The real table is `attune-ai/src/attune/models/registry.py:519-526`, with a fourth hand-copied rate pair in `ops/session_summarizer.py:42-48`. **`model_tiers.py`'s pattern cannot be mirrored eagerly**: the re-export there is lazy because `attune.config` must not pay for `attune_rag/__init__` (~350 modules), and exactly one module outside `cost_tracker.py` carries `from attune.models.registry import TIER_PRICING` at module scope — `agents/release/base_agent.py:22`, consumed at `:203` as `TIER_PRICING[tier.value]`. A repo-wide grep for `TIER_PRICING` under `attune-ai/src/attune/` returns five hits and no others: registry.py:519, cost_tracker.py:28 and :52, base_agent.py:22 and :203. With a single consumer outside cost_tracker.py, D5 is re-weighed in T1: converting base_agent.py:203 to a function-local import may remove the need for a drift guard entirely, and T2 ships the rate-equality guard in the same task as the rates rather than deferring it downstream. This plan moves the *numbers* (stdlib-only, no `ModelInfo`, no config-shaped converters) and leaves the dataclass and its converters where their consumers are.

Three further contradictions decide the gate work. `check_thresholds.check()` fails on `measured[metric] < threshold` for every metric and `measure_baseline_variance.compute_stats` emits `mean − σ·stdev` rounded to 4 dp, so a cost row in that file would fail a $0.0001 run, pass a $1.00 one, and round a Haiku-class figure to 0.0001 or to 0.0; the repo already solved the inverted case in `scripts/measure_perf_baseline.py` (`round(mean + sigma*stdev, 6)`, "inverted sign per Decision 1"), and this plan takes both the sign and the precision from it. `thresholds.json` is machine-generated — `write_thresholds_json` rebuilds the whole payload from `stats_by_metric`, so a hand-added cost row is destroyed by the exact re-measure command the gate's own failure comment tells maintainers to run; the row must be produced by the measuring script, which scrapes **stdout**, not the JSON dump, and `parse_metrics` uses `pat.search()` (first match wins), so the printed cost figure must appear exactly once per run. And there is no green-run comment to put a delta in — `format_failure_comment` raises `ValueError` on an empty failure list and benchmark.yml's comment step is gated on `steps.check.outputs.rc == '1'` — so this plan builds `scripts/format_cost_delta.py` on `perf.yml`'s `delta-check` pattern and adds an advisory job to `benchmark.yml`.

Three limitations stated at full strength. **Cross-repo execution.** The attune-ai side of the price-table move cannot ride in this file: `attune/spec/workspace.py:50-55` `_portable_path` raises `CommandWorkspaceError(["Spec artifact must be a project-relative path"])` for any path containing `..`, and `SpecArtifactReceipt.__post_init__` (workspace.py:77) runs it on every artifact path, so a `path="../attune-ai/…"` attribute is rejected downstream even though the regex parses it; the executor compounds it (`orchestrator._find_test_files` maps test files only for paths beginning `src/attune/`, and `_collect_source_files` resolves `../` strings against the attune-rag CWD). No plan in either repo has ever used a `..` path attribute. So T3 ships a companion plan file executed from the attune-ai repo root, every path repo-relative there, and this plan holds only the decision record and the cross-repo checks. **Measurement, not zero.** On this repo's default state `ANTHROPIC_API_KEY` is absent from Secrets (benchmark.yml's own header and its `HAS_KEY` branch say so), so a retrieval-only run spends nothing; every USD field is `None` on that path, never `0.0`. But null must not be a silent pass: T6 makes a null cost a **validation error (exit 2)** whenever the dump carries a faithfulness block whose `billing_mode` is `api`, so broken plumbing is loud and only a genuinely retrieval-only dump may omit the metric. **A failable surface today.** Locking a real cost threshold costs money (≥10 runs × 2 LLM calls per query), so the locked row lands via one deliberate maintainer-run lock. Until then the failable surface is named explicitly and is not the PR comment: the `--max-cost` ceiling wired into benchmark.yml's full-mode `FLAGS` (T7), and `smoke_check_gate.sh`'s synthetic-threshold cost cases, which run with `if: always()` on every PR and exercise the lower-is-better comparison for real (T6).
